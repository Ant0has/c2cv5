## Пользовательский сценарий

Страница «Эта страница не нашлась. Найдём вашу поездку» с лёгкой рисованной иллюстрацией (WebP 123 714 байт), полями «Откуда / Куда», перестановкой точек, локальными подсказками городов и свободным вводом. Существующий конструктор открывается только после отправки формы; на первоначальном экране запросов к его API нет.

Контактные ссылки используют общий справочник сайта. Переходы ведут в междугородние маршруты, море, горнолыжку, направления и на главную. Есть сценарии без JavaScript и при отключённом конструкторе. Новых пакетов, платных API, подписок и погодных блоков не добавлено.

События `not_found_pick_trip` и `not_found_recovery` передают только фиксированный тип действия, без введённых адресов и исходного URL. Цели в кабинете Метрики автоматически не создавались.

## HTTP и SEO

- Корневой и групповой not-found используют общий интерфейс. `/404` возвращает 404, `noindex, follow`, без canonical на главную.
- Групповой `app/(root)/loading.tsx` удалён, чтобы ранний streaming не превращал отсутствующие динамические страницы в HTTP 200; глобальный NavigationLoader сохранён.
- Для неизвестных `/napravleniya/*` и неразрешённых `.html` middleware передаёт локальному роутеру статус 404 через `NextResponse.next({ status: 404 })`, без абсолютного self-proxy. Действующие адреса и старые 301 не меняются.
- Политика Nginx для окончательно удалённых и неразрешённых `.html` остаётся **410**; не заменять её 404 или 200.
- Для полного серверного HTML ошибки применён ограниченный перехват 404 в Nginx. Шаблон: [helpful-404-location.conf.in](../deployment/helpful-404-location.conf.in), порт 3023. Только в frontend locations `/` и `~ \\.html$` добавлены `proxy_intercept_errors on;` и `error_page 404 =404 /404;`. Не добавлять на уровне всего сервера, API, CRM, статических ресурсов или 410-ответов. Точный `/404` не кешируется, не перехватывается повторно, очищает входные RSC-заголовки и сохраняет защитные заголовки. Адрес ошибки в браузере не меняется.

Причина воспроизведена: абсолютный rewrite на `/404` при `X-Forwarded-Proto: https` заставлял Next.js обращаться к собственному HTTP-порту по HTTPS. Финальное переключение в 13:47 МСК прошло все публичные проверки.

Операционная заметка: ещё до первого переключения прежняя 3022 автоматически перезапустилась в 13:18 МСК по ранее настроенному лимиту PM2 600 MiB (649 330 688 > 629 145 600 байт). Это не ручной перезапуск; настройки лимита не менялись. Остальные защищённые процессы не перезапускались.
