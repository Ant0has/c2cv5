## Исходники, Git и опубликованная сборка

29 изменений выпуска перенесены в основные исходники: 19 заменённых и 10 новых файлов. Активная сборка при этом живёт в отдельном release-каталоге. Старая `front/.next` оставлена для резерва; нельзя считать её сборкой новых исходников.

Production-дерево содержит и более ранние незакоммиченные изменения, включая работу над ценами. Они принадлежат Антону, не являются изменениями кода сегодняшней задачи о ссылках и не должны молча попадать в её коммит либо удаляться. Полный dirty production state, исходный Git HEAD и точечный коммит сегодняшней работы — разные состояния. Коммит сам по себе не доказывает воспроизводимость всей опубликованной сборки из чистого checkout.

В этой документации не утверждается, что коммит или push уже выполнены: результат Git фиксируется отдельно после фактической операции. Приватные снимки, окружение, исходные выгрузки Вебмастера с параметрами и резервные копии не предназначены для публикации в репозитории.

В [архиве выпуска](../ops/recorded-releases/2026-09-14/README.md) сохраняются точный sitemap, карта Nginx, дельта конфигурации и исходные изменения. Sitemap зафиксирован отдельным снимком: существовавшие до задачи 20 добавленных/15 удалённых URL и даты отличали production от старого Git HEAD. Рабочий `public/sitemap.xml` не переписывается ради чистого Git-статуса.

## Следующая публикация

**Старый `deploy.sh` без адаптации не запускать.** Он рассчитан на прежнюю `.next` и процесс на 3004, а публичный трафик уже обслуживает отдельный release на 3007. Также `npm start` из текущего `package.json` не переключает опубликованный сайт на новую сборку.

Перед следующим выпуском нужно заново сверить действующие Nginx, PM2, исходники и конфигурацию окружения; подготовить и проверить отдельную сборку; сохранять старую версию до проверки публичных страниц. Публикация должна учитывать и основную версию, и отдельный калькулятор. Команды из старых переписок и одноразовые запросы применения не повторяются без нового контроля состояния.

В этой поставке статические ресурсы двух версий объединены в пул из 450 файлов: прежние открытые вкладки и резервная версия могут догружать свои ресурсы. Не удалять его при уборке неиспользуемых кандидатов.
